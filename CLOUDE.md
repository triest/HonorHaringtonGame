# Дополнение: Impeller Wedge и кинематика Honorverse

## Impeller Wedge

Impeller wedge является фундаментальной частью физической и боевой модели Honorverse.

Он не является:

* визуальным эффектом;
* обычным энергетическим щитом;
* HP-based защитой;
* декоративной геометрией.

В симуляции wedge должен иметь реальную 3D-геометрию и участвовать в определении возможности воздействия оружия на корабль.

### Геометрия

Для стандартной модели корабля wedge создаёт защищённые плоскости:

* сверху;
* снизу.

Эти плоскости должны рассматриваться как практически непробиваемые для соответствующего вооружения.

Остаются потенциально уязвимыми направления:

* нос;
* корма;
* борта.

Бортовая защита моделируется через sidewall.

Следовательно, система должна различать:

```text
Wedge protection
    ↓
Top / Bottom

Ship geometry
    ↓
Bow / Stern / Broadside

Sidewall
    ↓
Broadside defensive layer
```

Это не должно быть сведено к одному параметру `shieldHP`.

---

## 3D orientation

Wedge должен быть связан с ориентацией корабля.

При изменении ориентации корабля автоматически изменяется:

* положение защищённых плоскостей;
* направление уязвимых зон;
* геометрия взаимодействия с оружием;
* допустимые направления атаки;
* визуальное отображение wedge.

Все проверки выполняются в 3D.

---

## Направление атаки

Для каждого воздействия необходимо определить относительный вектор:

```text
weapon → target
```

и сопоставить его с ориентацией корабля.

Система должна определить, откуда пришло воздействие:

* сверху;
* снизу;
* с носовой полусферы;
* с кормовой полусферы;
* с левого борта;
* с правого борта.

После этого применяется соответствующее правило защиты.

Нельзя использовать только расстояние между объектами.

---

# Кинематика

Корабли Honorverse должны моделироваться как высокоскоростные инерционные объекты.

Характерные особенности:

* огромные ускорения;
* ускорения порядка сотен g для соответствующих кораблей/технологических эпох;
* очень высокие скорости;
* скорости могут достигать существенной доли скорости света;
* огромные дистанции боя;
* существенное влияние относительной скорости.

Точные значения должны определяться конкретным кораблём, эпохой и доступными каноническими данными.

Не использовать одно глобальное значение:

```text
MAX_SPEED = X
```

для всех кораблей.

---

## Скорость

Внутренняя физическая модель должна использовать единицы, позволяющие корректно работать с релятивистски большими скоростями.

Для высоких скоростей необходимо учитывать:

* скорость света;
* долю `c`;
* относительную скорость;
* время полёта;
* distance;
* closure rate.

Если конкретная игровая механика требует приближения, оно должно быть задокументировано в `ASSUMPTIONS.md`.

---

## Acceleration

Ускорение корабля является физическим параметром.

Корабль не должен мгновенно менять velocity.

Управление должно приводить к:

```text
thrust
→ acceleration
→ velocity change
→ position change
```

с учётом:

* текущей velocity;
* направления тяги;
* ориентации;
* массы;
* compensator;
* propulsion state;
* damage.

---

## Relative velocity

Для боевой системы особенно важна относительная скорость.

Для двух объектов:

```text
relativeVelocity = targetVelocity - attackerVelocity
```

Она используется при:

* расчёте времени сближения;
* missile interception;
* targeting;
* weapon engagement;
* evasive maneuver;
* tactical AI;
* battle reports.

---

## Большие дистанции

Боевая сцена должна поддерживать реальные большие расстояния без необходимости искусственно сжимать пространство до размеров обычного космического dogfight.

Камера и UI могут использовать масштабирование для удобства игрока, но simulation coordinates не должны превращать реальные относительные расстояния в условную арену.

---

## Скорость света

Скорость света является фундаментальной физической константой simulation.

Нельзя допускать неконтролируемого прохождения скорости света объектами из-за простого:

```text
position += velocity * deltaTime
```

при больших значениях acceleration.

При необходимости использовать подходящую численную модель и ограничения, соответствующие выбранной физической аппроксимации.

Точная релятивистская модель должна быть введена только там, где она действительно необходима для игровой механики; инженерное упрощение должно быть задокументировано.

---

## Главное правило

В бою Honorverse положение корабля относительно собственного wedge является столь же важным, как расстояние до противника.

Поэтому tactical AI и player command должны учитывать:

```text
Enemy position
+
Enemy velocity
+
Enemy orientation
+
Enemy wedge geometry
+
Enemy sidewalls
+
Relative velocity
```

а не только:

```text
distance to enemy
```
